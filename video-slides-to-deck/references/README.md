# video-slides-to-deck

把**静态 PPT 讲解类视频**转成一份图文 HTML 要点文档。

---

## 一、适用边界（先读这里）

这套流程的每一步都建立在一个前提上：**画面是静止的幻灯片，而语音在解释这张幻灯片。**
前提不成立，切段、选帧、字幕提取这三步都会各自以不同的方式失败，而且失败得很安静。

### ✅ 适用

| 特征 | 说明 |
|---|---|
| 画面是幻灯片 | 标题 / 要点 / 图表 / 示意图，一屏一页 |
| 每页停留足够久 | 典型 5–90 秒，短于 3 秒的页会被合并掉 |
| 切换是硬切 | 一页直接换下一页，中间没有转场动画堆叠 |
| 有口播讲解 | 语音在讲屏幕上画的东西，不是闲聊、不是背景音乐 |
| 字幕烧录在画面上 | 底部黑条或白字，位置基本固定 |
| 页面之间有关联 | 一条完整的讲解线索，能写成"核心观点" |

典型例子：网课录屏里的 PPT 讲解、券商/基金的产品培训、学术报告 slides、
技术分享的 slide deck、部门内部的方案宣讲。

### ❌ 不适用

| 情况 | 为什么不行 |
|---|---|
| **口播 / 出镜讲解** | 画面是人，画面变化来自表情动作而不是换页。场景检测会切出一堆无意义的"切点"，关键帧全是相似的脸 |
| **录屏 / 软件操作演示** | 画面一直在动，场景检测会把每一次滚动、每一次点击都当成切点，段落数爆炸 |
| **快切剪辑 / 混剪 / 短视频** | 切换太快，候选帧落在转场中间，选出来的截图是模糊或半透明的 |
| **动画 / 动效视频** | 同一页 PPT 分十几步渐变出现，检测不到切点；就算检测到，选帧也没意义 |
| **没有语音** | 最关键的一步是"读出这一段在讲什么"。没有语音就没有内容可写，产出的只是一堆没有信息量的截图 |
| **语音和画面无关** | 比如背景是 B 站界面，语音在讲别的事；或者画面是实拍风景，语音是纯口播 |
| **纯音乐 MV / 混剪** | 同上，没有可提取的讲解内容 |
| **画面已被 PPT 导出成 PDF** | 那你手上已经有 PPT 了，不需要切视频 |

### 判断方法（动手前先做）

抽 3–4 帧，跨整个视频时间轴（比如 10% / 40% / 70% / 90%），然后问两个问题：

```powershell
ffmpeg -y -ss 60 -i video.mp4 -frames:v 1 f1.png
ffmpeg -y -ss 200 -i video.mp4 -frames:v 1 f2.png
```

1. **这几帧看起来像"一页幻灯片"，还是像"一段活动的画面"？**
   幻灯片 = 有标题、有排版结构、内容框住不动。
2. **底部有没有烧录字幕？**
   没有字幕 → 先确认能不能拿到音轨/官方字幕；都拿不到就**不适用**。

两个都满足 → 跑。有任何一条不满足 → 停下来说明，不要硬跑。

## 二、它做什么

```
视频
 ├─ ① 场景切分      ffmpeg 场景分检测 → 段落边界
 ├─ ② 候选帧        每段抽 3 张
 ├─ ③ 关键帧选择    视觉模型从 3 张里挑最有信息量的 1 张
 ├─ ④ 字幕还原      按段密集采样字幕条 → 顺序转录去重
 └─ ⑤ 成文          模型读字幕，写出每段真正的知识点总结（这步不能省）
        ↓
   一个 HTML：顶部核心观点 + 原视频链接 + 目录，28 页图文
```

### 为什么不能只用 ffmpeg

| 只做①不③ | 只做③不做① |
|---|---|
| ffmpeg 只会按固定间隔抽帧，抽出来的可能是转场瞬间、半透明动画、或白屏 | 视觉模型给不出"这段该在哪结束" |

### 为什么不能把 3 张候选帧分别发给模型

视觉模型对每张图**独立作答**。发 3 张问"选哪个"，会得到 3 个各自独立的意见，
不是一次选择。正确做法是拼成**一张带编号的联系表**，问编号 —— 一次调用，
答案可映射。

### 为什么总结必须自己写

自动摘要很容易退化成同义反复：

> ❌ 「买卖点全景图：买点的选择，关键在于要看不同级别之间是怎么配合的。」
> —— 把标题重说了一遍，等于没回答

> ✅ 「买点不是单一级别上的孤立形态，而是来自不同级别之间的配合——
> 大级别定方向、中级别定区域、小级别定精确入场点，三者叠加才构成有效买点。」
> —— 只读这一句，你就知道买点怎么来的

**判据：把视频关掉，只读总结，能不能学到这页的知识点？不能就是不合格。**

## 三、用法

```powershell
$py = "$env:USERPROFILE\miniconda3\python.exe"
$sk = "$env:USERPROFILE\.minimax\agents\mavis\skills\video-slides-to-deck\scripts"
$env:PYTHONIOENCODING = 'utf-8'
```

### 1. 先自检（强烈建议）

```powershell
& $py "$sk\selftest.py"
```

合成一段带标准答案的幻灯片视频，然后**扫描阈值**并告诉你可用区间。
输出 `PASS` 才说明阈值和分段逻辑真的没问题。

> 这一步存在的理由：ffmpeg 的场景阈值**不是文档化的常量**，而且是对整帧归一化的。
> 有标题栏和字幕条的幻灯片（固定不变的画面约占 1/3），真实切点分值会被压低到
> 0.076 这种量级。阈值一旦设高了，检测结果会是**零切点**，然后管线静默退化成
> "按时长均分"—— 看起来跑通了，其实全错。

### 2. 跑管线

```powershell
& $py "$sk\pipeline.py" "C:\path\video.mp4" --out "C:\path\out"
```

结束后会打印一张表：每段的时间区间、有没有关键帧、识别到几条字幕、字幕原文。
**这时候还没有标题和总结** —— 那是下一步的事。

### 3. 写内容

读那张表，给每一段写：

- `segments[i].title` —— 这段真正讲的主题
- `segments[i].summary` —— **自足**的知识点说明（见上面的判据）

再写 `meta`：

```json
{
  "title": "视频标题",
  "author": "UP 主",
  "url": "https://...",
  "core_points": [["小标题", "说明"], ["...", "..."]]
}
```

### 4. 渲染

```powershell
& $py "$sk\render_storyboard.py" "C:\path\out\storyboard.json"
```

出 `storyboard.html`，一个文件，图片内联，离线可用，浏览器直接打印即得 16:9 PDF。

## 四、参数

| 参数 | 默认 | 什么时候调 |
|---|---|---|
| `--scene-threshold` | `0.06` | 段落太少 → 调低；段落太多 → 调高（0.20–0.25，跳过动画渐变） |
| `--min-segment` | `5.0` | 有很多 3 秒的快闪页 → 调到 3 |
| `--max-segments` | `45` | 超长视频的兜底上限 |
| `--candidates` | `3` | 每段候选帧数。选帧质量不稳就加到 5 |
| `--sub-band` | `0.20` | 字幕条位置不同的视频。实测过的真实课件是 0.198–0.202 |
| `--sub-per` | `4.0` | 字幕采样间隔（秒）。长段落想更全就调到 2–3 |
| `--sub-max` | `12` | 每段最多采样点数 |
| `--cols` | `1` | 联系表列数。`1` 竖排，OCR 更准 |
| `--lang` | `zh` | 英文字幕视频改成 `en` |
| `--skip-subs` | — | 只想要截图不要字幕时用 |

### 实测参考值

ffmpeg 的场景分是**对整帧归一化**的，所以切点分值取决于"换页时画面到底变了多少"。
这也是为什么没有唯一正确的阈值，只有**可用区间**。

| 场景 | 真实切点分值 | 段内噪声 |
|---|---|---|
| 整屏换色（无装饰） | 0.156 / 0.187 / 0.168 / 0.290 / 0.263 | < 0.005 |
| 带标题栏 + 字幕条的幻灯片（装饰占约 1/3 画面） | 最低仅到 **0.076** | — |
| 真实 8.6 分钟缠论课件 | 0.175 ~ 0.229 | — |

**默认 0.06** ≈ 噪声底 12 倍，上面两种情况都能过。真实课件上验证：
0.06 得 33 切点、0.12 得 31 切点，段落数都是 28（多出的两个在 0.062 边界值，被
`--min-segment` 合并掉），没有误报爆炸。

> ⚠️ 常见的坑：很多教程说阈值设 0.3。那是整屏换色时的量级，套到有装饰的
> 幻灯片上会**一个切点都检测不到**，然后管线静默退化成"按时长均分"——
> 看起来跑通了，其实全部是错的。`selftest.py` 就是为了防这个。

### 自检怎么用

```powershell
& $py "$sk\selftest.py"                       # 扫描，输出可用区间
& $py "$sk\selftest.py" --threshold 0.06      # 钉死一个值判 PASS/FAIL
& $py "$sk\selftest.py" --quiet               # 一行摘要
```

样例输出：

```
  th     cuts  recall   prec    purity  cand    verdict
  0.04       5  100.0%  100.0%  100.0%  100.0%  PASS
  0.06       5  100.0%  100.0%  100.0%  100.0%  PASS
  0.08       4   80.0%  100.0%   80.0%   93.3%  fail
  0.12       2   40.0%  100.0%   66.7%   77.8%  fail
  0.2        0    0.0%    0.0%   66.7%   88.9%  fail
  weakest detected cut scored 0.076
  USABLE THRESHOLD RANGE: 0.04 .. 0.06
```

## 五、产物

```
out/
├── storyboard.html          ← 交付物，单文件
├── storyboard.json          ← 结构化记录（重渲染 / 接别的工具都用它）
├── candidates/              ← 每段 3 张候选帧
├── sheets/                  ← 每段一张带编号的联系表
├── substrips/               ← 每段一张字幕长条（人工核对字幕时看这个）
└── subcrops/                ← 裁出来的字幕条碎片
```

`storyboard.json` 里 `on_screen_text`（画面文字 OCR）**保留了但不在页面上显示** ——
画面上本来就能看到，重复展示是噪音；需要做检索或喂给别的工具时它在 JSON 里。

## 六、已知限制

- **拿不到官方字幕时**，字幕来自烧录字幕条的 OCR 识别，会有错字。同一句重复出现
  在画面上不同位置时可能重复或漏掉。管线内置了去重和污染过滤，但仍建议抽查
  `substrips/` 里的原图。
- **画面文字密集的页**（整页表格、代码）字幕识别会变差 —— 字幕条和正文重叠时尤其明显。
- **长静场**：一段讲十几分钟不换页，会被当成一个段落。可以靠 `--max-segments`
  和阈值调整，但本质上这类视频更适合当作音频转录处理而不是图文。
- **不做 PPTX**。需要 pptx 就把 HTML 打印成 PDF，或者另行转换。
